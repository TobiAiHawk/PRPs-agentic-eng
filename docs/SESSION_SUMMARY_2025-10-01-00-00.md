### 4. Context Optimization Documentation

Clarified 3-layer approach across all documents:

**Layer 1**: Agent Views (`PRPs/.cache/agent-views/`)
- 2-5KB per agent (vs 50KB+ full PRPs)
- Generated by `generate-agent-views.py`
- 90-95% context reduction

**Layer 2**: Context Loader (`.claude/context-loader.yaml`)
- Per-agent token limits (6-12K)
- Conditional loading rules
- Never-load exclusions

**Layer 3**: Task Briefs (`PRPs/.cache/task-briefs/`)
- Task-specific context only
- References to relevant PRP sections
- Minimal, focused context

## Architecture Decisions

### Decision 1: Separate Backlog/Active/Completed

**Rationale**:
- Clear visual indication of progress
- Easy to answer "what are we working on?"
- Prevents PRPs from lingering in ambiguous state

**Implementation**:
- Created subdirectories under planning/ and implementation/
- Added .gitkeep files to preserve structure
- Updated documentation with mv commands

### Decision 2: Comprehensive Lifecycle Documentation

**Rationale**:
- Users needed clarity on when to move PRPs
- Exit criteria per stage reduces confusion
- Examples prevent errors

**Implementation**:
- Created PRP-LIFECYCLE.md with 4 stages
- Added exit criteria checklists
- Included command examples for each transition

### Decision 3: 3-Layer Context Optimization

**Rationale**:
- Context minimization was implicit, needed explicit documentation
- Users should understand why views are generated
- Metrics prove effectiveness (90-95% reduction)

**Implementation**:
- Documented each layer separately
- Added size comparisons (50KB → 2-5KB)
- Included regeneration reminders throughout

## Usage Examples

### Starting a New Feature

```bash
# 1. Create PRP in backlog
cp PRPs/templates/prp_planning.md PRPs/planning/backlog/payment-feature.md

# 2. Move to active when starting
mv PRPs/planning/backlog/payment-feature.md PRPs/planning/active/payment-feature.md

# 3. Business Analyst refines
# In Claude Code: "Business Analyst, work on PRPs/planning/active/payment-feature.md"

# 4. Move to completed when done
mv PRPs/planning/active/payment-feature.md PRPs/planning/completed/payment-feature.md

# 5. Create implementation PRP
cp PRPs/templates/prp_base.md PRPs/implementation/in-progress/payment-impl.md

# 6. Generate views
python scripts/generate-agent-views.py --all

# 7. Implement
# In Claude Code: "Implementation Specialist, execute PRPs/implementation/in-progress/payment-impl.md"

# 8. Complete
mv PRPs/implementation/in-progress/payment-impl.md PRPs/implementation/completed/
```

### Checking Progress

```bash
# Quick dashboard
echo "Backlog: $(ls PRPs/planning/backlog/ 2>/dev/null | wc -l)"
echo "Active Planning: $(ls PRPs/planning/active/ 2>/dev/null | wc -l)"
echo "In Progress: $(ls PRPs/implementation/in-progress/ 2>/dev/null | wc -l)"
python scripts/agent-task-manager.py status
```
